# Methodology

## Scope

The prototype studies one narrow prediction task: short-horizon latency-risk classification for a cloud-native payment API. The system does not attempt to optimize infrastructure, schedule resources, or replace observability platforms.

## Data generation

The dataset is synthetic and generated by `src/data_generator.py`. Each row represents a fixed service-observability window. Features include:

- time context: hour, day of week, peak-hour flag, weekend flag
- operational context: deployment-window flag
- load indicators: requests per minute, queue depth
- resource indicators: CPU utilization, memory utilization, database connection saturation
- reliability indicators: dependency error rate, cold-start rate, cache hit rate
- response indicator: p95 latency in milliseconds

The target variable, `latency_risk`, is generated from a transparent probabilistic process. Higher risk is associated with high p95 latency, dependency failures, cold starts, queue depth, database saturation, deployment windows, and peak-hour traffic.

## Baseline method

The baseline is logistic regression with balanced class weights. It is included because it is simple, interpretable, and appropriate for checking whether a linear decision boundary captures the basic signal in the telemetry data.

## Improved method

The improved method is a random forest classifier. It remains lightweight and laptop-friendly while capturing nonlinear interactions, such as the combined effect of traffic pressure and deployment windows or dependency errors and database saturation.

## Evaluation

The experiment reports:

- Accuracy: overall correctness
- Precision: share of predicted risk windows that are truly risky
- Recall: share of true risk windows detected by the model
- F1 score: harmonic mean of precision and recall
- ROC-AUC: ranking quality across classification thresholds
- Average precision: precision-recall ranking quality, useful when risk windows are less frequent than normal windows

## Reproducibility

The experiment uses fixed random seeds. Running `python experiments/run_experiment.py` regenerates the dataset, trains both models, evaluates them, and writes outputs to `outputs/`.
